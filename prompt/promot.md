# 提示词
## 提示
> 我们现在要开发个本地用的文件内容查询系统。 主要功能是添加多个目录给系统， 系统就会扫描目录及子目录中的文件内容做牵引。 后面用户想要查询的时候可以快速查找到相关内容所在的文件。 差不多是个本地只搜索指定目录的搜索引擎。 这种功能是做成个web 服务好， 还是做成个软件使用方便？ 主要用 java 开发。
> 主要前期开发要求放在了 prompt/spec.md 文件中。 你理解后先作出技术造型和开发计划， 把整个系统分为几个阶段进行开发。 没有问题后我们就开始。 

四、分阶段开发计划

**阶段 1：索引与搜索核心（后端 MVP）**
- 项目骨架、H2 表结构、统一响应格式
- 索引库/目录 CRUD、目录递归扫描 + Tika 抽取 + Lucene 建索引
- 搜索 API（单库/全库、高亮摘要、分页）
- ✅ 验收：curl 完成建库→加目录→扫描→搜索全流程

**阶段 2：Web 界面**
- 查询页：结果列表（路径/文件名/摘要）、分页（默认 20）
- 设置页：索引存储位置、每页数量、默认库记忆
- 库与目录管理页、点击结果页内预览文件
- ✅ 验收：纯浏览器操作完成全部需求点

**阶段 3：健壮性与增量**
- 增量索引：WatchService 监听变更 + 启动时按 mtime/size 比对补漏
- 扫描异步化 + 进度展示、损坏文件跳过并记录、重建索引功能
- ✅ 验收：文件增删改后无需手动重建即可被搜到

**阶段 4：可选打磨**
- 服务的设置中增加可以设置端口的功能，并记录到配置中。
- 换索引数据目录时要求目录是空的， 并且可以把之前的索引数据迁移过去
- IK 分词可配置、按文件类型/时间过滤

> 阶段 1 2 3 4
> 写个 README.md 介绍项目如何编译运行，怎样使用， 尽量简短
> 你再写个启动脚本， 在任意目录运行它都可以启动服务
> 给我们项目创建一个 favicon.ico 文件， 要不然启动时会报错。
> 在点击显示文件内容时， 如果是 markdown 文件， 则需要渲染 markdown 内容。 支持高亮源码和渲染成 html 两种格式，可以点击按钮切换。如果要用到扩展 js 库， 用把库文件下载放到项目目录下分类存好， 然后在 html 中引入。
> 把添加目录时，系统支持的文件类型作为设置显示到设置页面中并保存配置， 用户可以修改，修改后只要以后建索引按配置就行了， 以前的可以不处理。
> 在打开文件显示时， 在上方用链接或按钮排列出所有匹配的位置， 用户点击可以快速跳转到匹配的位置。
> 打开文件时，显示的跳转链接不要用数字显示， 用匹配的内容作按钮文字。
